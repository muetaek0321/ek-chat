# Git コミット自動作成スキル

作業ツリーで変更されたファイル（ステージング済み・未ステージング）の内容を分析し、リポジトリの過去のコミット履歴規約に従って適切なコミットメッセージを生成し、必要に応じて変更を論理的な単位に分割してコミットを作成します。

---

## 基本方針

1. **過去のコミット規約の遵守**:
   - コミットを作成する前に必ず `git log` で過去の履歴を確認し、プロジェクトで定着しているコミット形式に従います。
   - このリポジトリの標準形式:
     - `[<type>] <変更内容の要約（日本語）>`
     - 代表的な type:
       - `[add]`: 新規機能、新規ファイル、新規モジュール・コンポーネントの追加
       - `[update]`: 既存機能の拡張・更新、設定変更、依存関係やドキュメントの更新
       - `[refactor]`: リファクタリング（外部仕様や振る舞いを変えないコード整理）
       - `[fix]`: バグ修正、不具合の改修
2. **関心事に応じたコミットの論理的分割**:
   - 変更されたファイルが複数存在する場合、`git diff` や `git status` で変更内容を精査します。
   - 変更内容が異なる関心事（例: BackendとFrontend、機能追加とドキュメント更新、リファクタリングとバグ修正など）に分けられる場合は、一括でコミットせず、関連するファイルごとに `git add` して分割してコミットを作成します。
   - 密接に関連する変更（例: APIエンドポイントの変更とそれを利用するフロントエンド側の型定義の修正など）は、整合性を保つため1つのアトミックなコミットにまとめます。
3. **エージェント識別情報の記録 (Git Trailer)**:
   - エージェント（AI）が作成したコミットであることが後から明確に判別・追跡できるように、コミットメッセージの末尾（Git Trailer）にメタデータを記録します。
   - タイトル（1行目）にはモデル名を含めず、コミットメッセージ末尾（空行を挟んだTrailer領域）に以下の形式で記録します：
     ```gitcommit
     AI-Agent: <エージェント名>
     AI-Model: <モデル名>
     Co-authored-by: <エージェント名> <<メールアドレス>>
     ```
     - 記載例:
       ```gitcommit
       AI-Agent: GitHub Copilot
       AI-Model: Claude Sonnet 4.5
       Co-authored-by: GitHub Copilot <noreply@github.com>
       ```
     - ※ 使用しているエージェント環境（例: `GitHub Copilot`、`Antigravity` など）およびモデル名（例: `Claude Sonnet 4.5`、`Gemini 3.8 Flash` など）に応じて適切な値を設定します。
4. **作業範囲の保護と安全性 (`AGENTS.md` の遵守)**:
   - 秘密情報（`.env`、APIキー等）やビルド成果物、不要な一時ファイルが含まれていないことを確認します。
   - コミット前に、対象領域（`backend` / `frontend`）のリンター・フォーマッター・テストでエラーがないか確認します。
   - ユーザーから明示的な指示がない限り、`git push` やリモート操作は行いません。

## 手順・アクションフロー

### 1. 変更状態の確認

現在の作業ツリーの差分とステータスを確認します。

```bash
git status -s
git diff
```

### 2. コミット履歴・スタイルの確認

直近のコミットメッセージ形式を確認します。

```bash
git log -n 15 --oneline
```

### 3. コミット分割の検討とグルーピング

変更されたファイル群を以下の観点で分析し、コミットをいくつに分けるか決定します。

| 分割の観点         | 例                                                                     | コミット方針                             |
| ------------------ | ---------------------------------------------------------------------- | ---------------------------------------- |
| **領域の分離**     | `backend/` 配下の変更 と `frontend/` 配下の変更                        | 独立した変更であれば分割                 |
| **役割の分離**     | 機能コードの追加/更新 と ドキュメント（README/Docstring/スキル）の更新 | 原則として別コミットに分割               |
| **変更種別の分離** | リファクタリング（リネーム・移動等） と 新機能追加/バグ修正            | 原則として別コミットに分割               |
| **密結合な変更**   | APIの型変更 と そのクライアント実装の変更                              | 動作整合性を保つため 1つのコミットに集約 |

### 4. 品質検証の確認

変更ファイルに構文エラーやスタイル違反がないか、`AGENTS.md` の規定に従いチェックします。

- Backend変更時: `uv run ruff check .` / `uv run pytest` など
- Frontend変更時: `yarn lint` / `yarn test` など

### 5. ステージングとコミットの実行

グループごとにファイルをステージングし、規約に沿ったメッセージおよびTrailerを付与してコミットを作成します。
Gitでは `-m` オプションを複数指定することで、タイトル・本文・Trailerを空行区切りで作成できます。

```bash
# 本文なし（タイトル + Trailer）の場合
git add <対象ファイル群>
git commit -m "[<type>] <要約（日本語）>" \
  -m "AI-Agent: <エージェント名>
AI-Model: <モデル名>
Co-authored-by: <エージェント名> <<メールアドレス>>"

# 本文（詳細説明）を含む場合
git add <対象ファイル群>
git commit -m "[<type>] <要約（日本語）>" \
  -m "<変更の背景や詳細説明>" \
  -m "AI-Agent: <エージェント名>
AI-Model: <モデル名>
Co-authored-by: <エージェント名> <<メールアドレス>>"
```

※ PowerShell等で改行を含むコマンドを実行する場合は、適切な改行エスケープ（バッククォート `` ` ``）を用いるか、ヒアドキュメント・一時コミットメッセージファイルなどを利用してください。

### 6. コミット結果の確認と報告

作成されたコミットログを確認し、ユーザーにコミット内容を報告します。

```bash
git log -n 5
```

## コミットメッセージの作成例

### タイトル行の種別例

- 新規スキルや機能を追加した場合:
  - `[add] コミット自動作成スキルを追加`
  - `[add] チャット履歴のエクスポート機能を追加`
- 既存機能を改修・アップデートした場合:
  - `[update] 返答生成中にSendアイコンに被せてサークルプログレスを表示するように改修`
  - `[update] Geminiのモデル自動選択処理のエラーハンドリングを強化`
- コードの整理・リファクタリングの場合:
  - `[refactor] チャット画面のコンポーネント構造を整理`
- 不具合を修正した場合:
  - `[fix] ストリーミング受信時の改行コード処理の不具合を修正`

### コミットメッセージ全体の完成例

#### パターン1: タイトル + Trailer（通常）

```gitcommit
[add] コミット自動作成スキルを追加

AI-Agent: GitHub Copilot
AI-Model: Claude Sonnet 4.5
Co-authored-by: GitHub Copilot <noreply@github.com>
```

#### パターン2: タイトル + 詳細説明 + Trailer

```gitcommit
[update] 返答生成中にSendアイコンに被せてサークルプログレスを表示するように改修

返答の生成処理中であることが視覚的に分かりやすくなるよう、Sendボタン上にインジケータを重ねて描画する処理を追加。

AI-Agent: GitHub Copilot
AI-Model: Claude Sonnet 4.5
Co-authored-by: GitHub Copilot <noreply@github.com>
```

## 呼び出し例

ユーザーが以下のように要求した際に本スキルを起動します：

- `変更内容をコミットして`
- `適切な単位に分けてコミットを作成して`
- `git commitして`
- `この作業内容を過去の形式に合わせてコミットして`
